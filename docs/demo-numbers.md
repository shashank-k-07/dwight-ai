## Caveats (say these if asked)

1. Every dollar figure is labelled Measured (tokens actually used x list price) or Estimated (projected). The model never produces a dollar figure; code prices tokens from data/prices.yaml.
2. The token drop is Measured on the real layer: the same 10 storage tasks run before and after loading the Draft, same model and settings, only the context files changed. It is an average over the 10 tasks (tokens per Session), not a gain on every task.
3. Not every task got cheaper: t07-savings-ranking (+35.4% tokens, $4.44 -> $6.11 Measured) cost more after the Draft.
4. It is the second Draft attempt. Draft v1 held task success at only 8/10 (-28.3% tokens), so it did not count; its runs are archived in data/archive/draft-v1-after-runs/. The Drafter was fixed (keep the table columns that rules depend on; the Draft replaces the source docs) and the whole after batch was run once with Draft v2. No re-runs or tuning after that.
5. Real-layer Spend is priced as uncached input: Sciforium reports no cached-token counts, so no cache discount can be Measured there.
6. Cache Miss and Model Overkill appear in the synthetic layer only: Cache Miss is not observable on a provider that reports no cache reads, and the real layer runs Flash models only, so there is no overkill.
7. The synthetic layer is generated (ticket 07); its Spend is a fictional company's month. The real layer is the harness runs (tickets 03, 04, 16).
